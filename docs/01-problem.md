# 1. 문제 정의

## 사용자가 겪는 문제

가전제품이 고장 났을 때 사용자는 세 가지 벽에 부딪힌다.

**① 설명서를 안 읽는다 / 못 찾는다.** 종이 설명서는 이미 버렸고, PDF는 평균 57쪽(최대 100쪽)이다.
"삐 소리가 나고 문이 안 닫혀요" 같은 실제 증상을 설명서의 목차 언어("도어 열림 알림 기능",
"수평 조절")로 번역해야 원하는 쪽에 닿는다.

**② 검색해도 내 모델 정보가 아니다.** 같은 "LG 세탁기"라도 드럼과 통돌이는 에러코드 체계가 다르고,
같은 드럼이라도 모델에 따라 있는 기능과 없는 기능이 갈린다. 블로그·커뮤니티 검색 결과는 어느 모델
기준인지 불분명하고, 틀려도 확인할 방법이 없다.

**③ 제조사 챗봇은 브랜드에 갇혀 있다.** LG 챗봇은 LG 제품만, 삼성 챗봇은 삼성 제품만 답한다.
집에 LG 세탁기와 삼성 냉장고가 같이 있는 게 보통인데, 두 창구를 따로 써야 한다.

## 왜 LLM 단독으로는 안 되는가

범용 LLM에 "LG 드럼세탁기 dE 에러가 뭐야"라고 물으면 그럴듯한 답이 나온다. 문제는 그 답이
**내 모델 설명서에 실제로 적힌 내용인지 확인할 수 없다**는 점이다. 가전 문제는 오답의 비용이 크다.
"전원을 껐다 켜라"를 잘못 안내하면 시간 낭비로 끝나지만, 안전 경고를 빠뜨리거나 반대로 안내하면
감전·화재 위험으로 이어진다.

그래서 이 프로젝트는 **답변의 모든 문장이 특정 모델의 설명서 원문에서 나와야 한다**는 제약을
설계의 출발점으로 삼았다.

## 우리가 만든 것

사용자가 자기 가전을 등록해두면, 그 **모델의 설명서만을 근거로** 질문에 답하는 챗봇.

| 사용자 질문 | 시스템 동작 |
|---|---|
| "dE 에러가 나고 문이 안 닫혀요" | 에러코드 DB에서 `dE` 정확 매칭 → 원인·조치 + 제조사 사진 |
| "세탁통 청소 어떻게 해요?" | 등록 모델 설명서에서 청소 절차 검색 → 단계별 답변 + 각 단계의 설명서 그림 |
| "이 모델에 건조 기능 있어요?" | 모델별 기능 표 조회 → "이 모델에는 없습니다" 확정 답변 |
| "전자레인지가 안 돌아가요" | 등록 가전이 아님을 감지 → 제품 등록 안내 |

## 설계 목표와 우선순위

| 우선순위 | 목표 | 판단 기준 |
|---|---|---|
| 1 | **근거 없는 답을 하지 않는다** | 설명서에 없는 내용을 자신 있게 말하는 경우(FALSE_CONFIDENCE) 0건 |
| 2 | **모델별로 맞는 답을 한다** | 등록 모델의 설명서만 검색 범위로 사용 |
| 3 | **근거를 보여준다** | 답변마다 출처 쪽 번호 + PDF 원문 + 해당 그림 |
| 4 | **답변이 실제로 쓸모 있다** | 근거에 있는 확인 항목을 누락 없이, 이유와 함께 제시 |

3번(근거 제시)과 4번(풍부함)이 충돌할 때는 3번을 택했다. 모르면 "설명서에서 찾지 못했습니다"라고
답하는 쪽이, 그럴듯하게 지어내는 쪽보다 낫다고 판단했다.

## 제조사 챗봇 대비 우리 시스템의 위치

이 프로젝트가 제조사 챗봇보다 답변 품질이 항상 낫다고 주장하지 않는다. 실제로 LG 공식 챗봇과
같은 질문을 비교해보면, 제조사 쪽이 더 많은 부가 정보(관련 팁, 주변 상황 안내)를 준다.

다만 "제조사 챗봇은 자기 제품이니 정확할 것"이라는 가정도 항상 맞지는 않는다. 실제 사례 하나를
직접 확인했다. LG 온라인 사이트에 실제 보유 에어컨(`SNC063BAW.AKOR2`)을 등록하고 "이 에어컨
리모컨 사용 방법 알려줘"라고 물었더니, LG 챗봇은 일반적인 에어컨 리모컨 명칭(MODE·FAN·SWING·
JET·TIMER·SLEEP)으로 답했다. 같은 모델의 실제 설명서(구매 시 받은 PDF, p.14)를 직접 읽어
대조하면:

| 항목 | LG 챗봇 답변 | 실제 설명서 |
|---|---|---|
| 모드 전환 | "MODE 버튼으로 냉방/제습/**난방**/송풍 선택" | 이 모델엔 난방·송풍 기능 자체가 없다. "운전선택" 버튼으로 냉방↔제습만 순환 |
| 바람 방향 | "SWING(**좌우**/상하 화살표) 버튼" | 좌우 스윙 없음. "풍향상하"(상하만) |
| 강력 냉방 | "JET/POWER/강풍" | 실제 버튼명은 "파워냉방" |
| 예약 | "TIMER 또는 시계 모양 버튼" | "취침/꺼짐예약"(하나로 결합된 버튼) |
| 취침·절전 | "SLEEP/절전 버튼" | "절전"과 "취침/꺼짐예약"은 별개 버튼 |

일반적인 버튼 명칭으로 답하면서 이 모델에 없는 기능(난방, 좌우 스윙)까지 있는 것처럼 안내한
것이다. 사례 1건이라 일반화할 수는 없고, 이 모델은 우리 60개 데이터셋에도 없어 같은 질문에
우리 시스템이 더 잘 답한다고 직접 비교하지는 못했다. 다만 "특정 모델 설명서에 실제로 적힌
내용만 근거로 한다"는 이 프로젝트의 제약([설계 목표 1번](#설계-목표와-우선순위))이 겨냥하는
실패 유형이 제조사 챗봇에서도 실제로 관찰된다는 근거로는 의미가 있다.

이 프로젝트의 900문항 평가에도 "리모컨" 사용법을 묻는 질문이 실제로 포함돼 있다(round2, 20문항 —
[05-evaluation.md](05-evaluation.md#52-평가-질문셋)).

대신 다음 네 가지는 구조적으로 우리 쪽이 갖는 이점이다.

1. **브랜드 통합** — LG·삼성을 한 창구에서. 등록한 가전 목록으로 관리한다.
2. **출처 추적** — 모든 답변에 쪽 번호와 PDF 원문 링크, 해당 그림이 붙는다.
3. **측정된 근거성** — 서비스 경로 600문항(round1·2) 평가에서 LLM 판정 기준으로 근거 없는 확신 답변이 관측되지 않았다
   (확정 수치는 아님, 한계는 [05-evaluation.md](05-evaluation.md#510-한계)).
4. **영업 동기 없음** — 상담 예약·유상 수리 유도가 답변 생성에 개입하지 않는다.

## 범위

**포함:** LG·삼성 에어컨·냉장고·세탁기 계열 60개 모델의 설명서 기반 질의응답, 에러코드 조회,
모델별 기능 유무 판정, 설명서 그림 제시.

**미포함:** 실제 수리 예약, 부품 주문, 사용자별 수리 이력 관리, 음성 인터페이스.
제품 등록을 통한 개인화는 모델 범위 한정까지만 구현했고, 사용 패턴 학습은 범위 밖이다.
