## 설명서 PDF

제품군 8종에 걸쳐 60개 모델을 수집했다. 폴더는 대분류 3개(`aircon`/`fridge`/`washer`)로 나누고,
실제 제품군은 `product_type`으로 구분한다.

| 제품군 | 개수 | 제품군 | 개수 |
|---|---|---|---|
| 에어컨 | 20 | 세탁건조기 | 4 |
| 냉장고 | 17 | 스타일러 | 3 |
| 세탁기 | 8 | 김치냉장고 | 3 |
| 건조기 | 3 | 슈드레서 | 2 |

쪽수는 최소 16쪽, 최대 100쪽, 평균 57쪽이다.

**PDF는 Git에 포함하지 않는다.** 총 537MB이고 제조사 저작물이기 때문이다. 팀원은 공유 드라이브에서
받거나, 공유 DB 모드에서는 서버가 Supabase Storage에서 자동으로 내려받는다([06-setup.md](06-setup.md)).

### 브랜드별 문서 구조 차이

같은 "사용설명서"라도 제작 도구가 달라 내부 구조가 다르다. 청킹 전략이 여기서 갈린다.

| | LG | 삼성 |
|---|---|---|
| 제작 도구 | FrameMaker 계열 | InDesign 계열 |
| 목차 북마크 | 최신 20개 중 17개 내장 | 30개 중 27개 내장 |
| 고장 신고 | `[증상 \| 원인 및 해결책]` 표 | 세탁기류는 표, 에어컨·냉장고는 표 없는 텍스트 |
| 트러블슈팅 챕터명 | "고장 신고 전 확인하기" | "서비스를 요청하기 전에" |

목차 북마크가 없거나 손상된 PDF(구형 모델, 삼성 2개)는 폰트 크기 기반 폴백으로 처리한다.

## 에러코드 (관계형 데이터)

에러코드는 벡터 검색에 맡기지 않고 별도 테이블로 분리했다. `dE`, `CH04` 같은 코드는 **정확히
일치하거나 아니거나** 둘 중 하나라서, 유사도 점수로 근사할 문제가 아니기 때문이다.

| 브랜드 | 에어컨 | 냉장고 | 세탁기 |
|---|---|---|---|
| LG | 11 | 5 | 10 |
| 삼성 | 13 | 4 | 8 |

**코드 정규화**가 조회의 핵심이다. 같은 에러가 표기만 다르게 쓰이는 경우가 많다.

- `CH05` → `CH5` (숫자 앞 0 제거)
- `Er(E) FF` → `ERFF`, `EFF`, `FF` (괄호 안 대안 표기를 모두 별도 행으로)
- `0E` ↔ `OE`, `1E` ↔ `IE` (사용자가 헷갈리기 쉬운 문자는 양방향 등록)

한 코드가 두 항목에 걸칠 수도 있다(LG 에어컨 `F4`는 냉매 부족과 시운전 보호 양쪽). 이 경우 둘 다
반환하고 LLM이 질문 맥락으로 고르게 한다.

## 모델별 기능 표

"이 모델에 클린봇 기능 있어요?"에 답하려면 **없다는 사실**을 확정할 수 있어야 한다. 벡터 검색으로는
"언급이 없음"과 "검색에 실패함"을 구분할 수 없어서, LG 설명서 부록의 모델별 기능 표를 별도로 파싱했다.

```
model_pattern  feature    has
FQ**FN9***     클린봇      1
FQ**FN7***     클린봇      0
```

모델명을 패턴과 대조해(`FQ18FN9ABC` → `FQ**FN9***` 일치) 있음/없음을 판정한다. 표가 없는 모델은
"모름"으로 떨어지고 일반 검색으로 넘어간다. 삼성은 이 표가 없어 현재 LG만 지원한다.

## 에러코드 사진

LG 고객지원 페이지에는 에러코드별로 표시부 사진과 조치 그림이 있다. 이를 수집해 에러코드 항목에
연결했다(`scripts/crawl_error_images.py`). 세탁기는 드럼·통돌이 페이지가 따로라 `variant`로 기록하고,
사용자 모델명으로 골라 쓴다.

**저작권 취급:** 제조사 저작물이므로 저장소에 올리지 않고 로컬 캐시만 한다. 화면에는 항상
"이미지 출처: LG전자 고객지원" 링크를 함께 표시한다. 삼성 고객지원 페이지는 확인한 범위에서
본문 사진이 없어 텍스트만 사용한다.

## 데이터 구축 파이프라인

```
PDF 60개 ──► 청킹 (목차 기반)         ──► 청크 6,105개 ──► 임베딩 ──► 벡터 DB
        └──► 부록 기능 표 파싱         ──► model_features
        └──► 파일명·부록에서 모델 추출  ──► manual_models

제조사 고객지원 페이지 ──► 에러코드 JSON ──► error_entries / error_codes
                     └──► 사진 크롤링    ──► data/error_images/
```

- 청킹·인덱싱: `experiments/박형건_exp02.py`, `experiments/siyeon/rag/chunking_*.py`
- 관계형 DB 구축: `experiments/siyeon/rdb/build_db.py` → `data/appliance.sqlite`
- 에러코드 사진: `scripts/crawl_error_images.py`
- 공유 DB 이전: `scripts/migrate_to_postgres.py`

## 평가용 질문셋

모델 60개 × 3라운드 × 5문항 = **900문항**을 고정 질문셋으로 쓴다(`experiments/harness/evaluate.py`).

질문에 모델명을 직접 포함시켜("FQ18GC1EHN 에어컨 필터 청소 방법 알려줘") 60개 모델이 전부 최소
15번씩 검증되게 했다. 초기에는 22문항 공통 질문을 썼는데, 그러면 60개 모델 중 39개만 검색에 걸리고
21개는 한 번도 검증되지 않는 문제가 있었다.

자세한 평가 설계는 [05-evaluation.md](05-evaluation.md)를 참고한다.
