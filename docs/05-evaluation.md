# 5. 평가 지표와 결과

## 5.1 무엇을 측정해야 하는가

RAG 평가에서 흔히 쓰는 "정답률"은 이 문제에 그대로 맞지 않는다. 설명서에 **없는 내용을 묻는 질문**이
섞여 있기 때문이다. 이때 "찾지 못했습니다"는 실패가 아니라 **정답**이다.

그래서 답변을 4가지로 분류한다.

| 라벨 | 의미 | 평가 |
|---|---|---|
| `SUCCESS` | 근거가 있고 그 근거로 제대로 답함 | 성공 |
| `GENUINE_NO_ANSWER` | 설명서에 정말 없어서 못 답함 | **정상** (실패 아님) |
| `FALSE_DECLINE` | 근거가 있는데 "없다"고 포기함 | 실패 (놓침) |
| `FALSE_CONFIDENCE` | 근거가 없는데 자신 있게 답함 | **가장 나쁜 실패** |

`FALSE_CONFIDENCE`를 가장 무겁게 본다. 사용자가 틀렸다는 걸 알아챌 방법이 없고, 가전 문제에서는
안전과 직결될 수 있기 때문이다.

판정은 gpt-4o-mini에게 (질문, 답변, 실제 근거 청크)를 주고 4분류를 시킨다
(`experiments/harness/evaluate.py`의 `judge_results`).

## 5.2 평가 질문셋

모델 60개 × 3라운드 × 5문항 = **900문항**. 질문에 모델명을 직접 포함시켜 60개 모델이 전부 최소
15번씩 검증되게 했다.

| 라운드 | 질문 성격 |
|---|---|
| round1 | 기본 사용법·청소·증상 (필터, 소음, 냉방, 에러 등) |
| round2 | 좀 더 구체적인 기능·코스·설정 |
| round3 | 스펙 조회, 예외 상황 |

초기에는 22문항 공통 질문을 썼는데, 그러면 60개 모델 중 39개만 검색에 걸리고 21개는 한 번도
검증되지 않았다. 청킹 버그가 있어도 하필 그 모델이 안 걸리면 못 잡아낸다는 뜻이라 모델명을 포함한
질문셋으로 교체했다.

## 5.3 최종 결과 — 실제 서비스 경로 (round1 300문항)

**측정 대상이 실제 웹 서비스 경로다.** 실험용 `my_answer()`가 아니라 `web/rag_service.py`의
`retrieve` + `stream_answer`를 그대로 호출했다(`experiments/web_baseline_eval.py`).

| 라벨 | 개수 | 비율 |
|---|---|---|
| SUCCESS | 277 | **92.3%** |
| GENUINE_NO_ANSWER | 20 | 6.7% |
| FALSE_DECLINE | 3 | 1.0% |
| **FALSE_CONFIDENCE** | **0** | **0%** |

**근거 없이 지어낸 답변이 한 건도 없다.** 설계 목표 1번([01-problem.md](01-problem.md#설계-목표와-우선순위))을
충족한다.

실패 23건 중 12건이 "에러 메시지 확인하는 방법" 유형이다. 질문에 에러코드가 없으면 RDB 경로를 타지
못하고, 벡터 검색이 "고장 진단하기" 섹션을 놓치는 경우가 있다. 이 유형은 개선 여지로 남아 있다.

## 5.4 실험 단계 결과 (참고)

통합 이전, 개인 실험 파이프라인(`박형건_exp02`)을 900문항 전체로 돌린 기록이다. 서비스 경로와는
프롬프트·라우팅이 달라 직접 비교 대상은 아니다.

| 라운드 | 키워드 히트율 | SUCCESS | GENUINE_NO_ANSWER | FALSE_DECLINE |
|---|---|---|---|---|
| round1 | 99.0% | 230 | 52 | 18 |
| round2 | 86.3% | 216 | 74 | 10 |
| round3 | 87.7% | 224 | 66 | 10 |

라운드가 올라갈수록 질문이 구체적·예외적이라 `GENUINE_NO_ANSWER`가 늘어난다. 설명서에 없는 내용을
묻는 질문이 실제로 많다는 뜻이다.

## 5.5 검색 품질 (오프라인 지표)

정답 청크를 사람이 라벨링한 97케이스로 측정했다(`experiments/results/retrieval_metrics_offline.json`).

| 지표 | 값 |
|---|---|
| MRR | 0.627 |
| Precision@1 | 0.474 |
| Recall@5 | 0.825 |
| Recall@10 | 0.928 |
| Recall@40 | 0.990 |

**Recall@40이 99%인데 P@1이 47%라는 게 핵심이다.** 1차 벡터 검색은 정답을 거의 놓치지 않지만 순서를
제대로 못 매긴다. 그래서 후보를 넓게(40개) 뽑고 리랭킹에 순서를 맡기는 구조를 택했다.

리랭킹 정확도는 같은 97케이스에서 **정확 매칭 94 / 놓침 3**이었다(`quant_llm_rerank_97.json`).

## 5.6 RAGAS 지표

| 라운드 | Faithfulness | Answer Relevancy |
|---|---|---|
| round1 | 0.881 | 0.575 |
| round2 | 0.778 | 0.479 |
| round3 | 0.789 | 0.465 |

**Faithfulness(근거 충실도)는 높고 Answer Relevancy는 낮게 나온다.** 이 격차는 지표의 성질 때문으로
본다. RAGAS의 Answer Relevancy는 답변에서 질문을 역생성해 원 질문과의 유사도를 재는데, 우리 답변은
"설명서에 따르면", "그래도 해결되지 않으면 고객센터에 문의하세요" 같은 정형 문구를 규칙으로 강제한다.
이 문구들이 역생성 질문을 흐려서 점수를 깎는다.

즉 **Answer Relevancy가 낮다는 것이 답변이 나쁘다는 뜻은 아니다.** 같은 답변을 4분류로 판정하면
SUCCESS가 92.3%다. 지표 하나만 보고 판단하지 않기 위해 세 가지(4분류·오프라인 검색 지표·RAGAS)를
함께 본다.

## 5.7 그림 매칭 품질

| 항목 | 값 |
|---|---|
| 그림이 붙은 답변 | 122 / 300 (41%) |
| 그림 후보가 있는 근거를 쓴 답변 | 223 / 300 |
| 정밀도 (무작위 28쌍 눈 검수) | 약 93~96% |

정밀도를 재현율보다 우선했다. 틀린 그림을 보여주느니 안 보여주는 쪽이 낫다는 판단이다.
검수 중 발견한 오류 1건(세탁물 넣기 단계에 세제함 그림)은 그림 위 글을 모을 때 문단 경계를 넘던
문제로 확인해 수정했다.

## 5.8 공유 DB 전환 동등성

로컬(SQLite + Chroma)에서 공유 DB(Postgres + pgvector)로 바꿔도 **검색 결과가 달라지지 않아야 한다.**
전환 전 로컬 pgvector로 대조 검증했다.

| 검증 항목 | 결과 |
|---|---|
| 벡터 검색 상위 40개 순서 | 무작위 질의 80건 **100% 일치** |
| 거리 값 오차 | 최대 6e-7 |
| `get(ids)` 반환 순서·내용 | 200회 전부 일치 |
| 매뉴얼 조회 | 60 / 60 일치 |
| 에러코드 조회 | 72 / 72 일치 |
| 모델별 기능 유무 (GLOB→LIKE) | 132 / 132 일치 |

검증 과정에서 두 가지를 발견해 고쳤다. Chroma의 `get(ids)`는 요청한 순서가 아니라 컬렉션 내부
순번으로 돌려준다는 점(리랭킹 후보 순서에 영향), 그리고 Postgres의 한글 정렬이 SQLite와 다르다는 점이다.

## 5.9 한계

- **판정자가 LLM이다.** 4분류는 gpt-4o-mini의 판단이며, 사람 검수와 완전히 일치하지 않는다.
  실제로 판정 프롬프트의 결함(제목과 본문을 혼동)을 발견해 수정한 이력이 있다.
- **그림 매칭 표본이 작다.** 정밀도 93~96%는 무작위 28쌍 눈 검수 기준이라 참고치다.
- **재현율은 측정하지 못했다.** 그림 매칭에 정답 라벨이 없다.
- **round2·round3는 서비스 경로로 재측정하지 않았다.** 현재 92.3%는 round1 300문항 기준이다.

## 재현 방법

```bash
# 실제 서비스 경로 평가 (round1 300문항) — OpenAI 비용 발생
python experiments/web_baseline_eval.py            # 전체
python experiments/web_baseline_eval.py --n 5      # 파일럿
python experiments/web_baseline_eval.py --resume   # 중단 지점부터

# 결과: experiments/results/web_baseline_round1.json
```

실험용 개별 파이프라인 평가는 [`experiments/README.md`](../experiments/README.md)를 참고한다.
