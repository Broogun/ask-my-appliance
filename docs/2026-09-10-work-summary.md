# 2026-09-10 작업 정리

## 1. LG 데이터 수집 완료 (에어컨/냉장고/세탁기 각 10개)

LG 공식 매뉴얼 다운로드 페이지(`lge.co.kr/support/product-manuals`)에서 실제 판매 모델의
사용설명서 PDF를 직접 다운로드했다. 쿠팡 기준 수집은 접근 차단(403/확장프로그램 차단)으로
불가해 LG 공식 홈페이지 기준으로 전환했고, "판매 모델명"과 매뉴얼 검색용 "SVC 코드"가
다른 체계라는 점도 확인하고 대응했다.

| 카테고리 | 모델 수 | 파일 위치 |
|---|---|---|
| 에어컨 | 10 | `data/manuals_pdf/lg/aircon/` |
| 냉장고 | 10 | `data/manuals_pdf/lg/fridge/` |
| 세탁기 | 10 | `data/manuals_pdf/lg/washer/` |

냉장고/세탁기는 서브카테고리를 다양하게 섞었다:
- **냉장고**: 양문형, 상냉장/하냉동, 정수기형, 일반형, 스탠드형 김치냉장고, 뚜껑형 김치냉장고
- **세탁기**: 드럼, 통돌이, 워시타워, 미니세탁기, 의류건조기, 의류관리기

`data/manuals_pdf/{lg,samsung}/{aircon,fridge,washer}/` 브랜드×카테고리 구조로 재정리했고,
기존에 흩어져 있던 PDF도 전부 이 구조로 이동시켰다. **삼성은 아직 비어있음 (내일 진행 예정)**.

## 2. 청킹 + 임베딩 (벡터 DB)

`scripts_batch_ingest_all_lg.py`로 30개 PDF를 전부 청킹 → OpenAI 임베딩 → Chroma
(`appliance_manuals_openai` 컬렉션)에 upsert.

- PDF 내장 TOC(북마크) 기반 청킹을 기본으로 쓰고, TOC가 없는 문서만 폰트 크기 휴리스틱으로
  폴백 (`pipeline/pdf_chunker.py`)
- 총 **2,185개 청크** (에어컨 776 / 냉장고 501 / 세탁기 908)

## 3. 에러코드 RDB 확장 (에어컨 → 냉장고·세탁기까지)

기존에는 에어컨 에러코드만 RDB(`data/error_codes.db`)에 있었음. LG 공식 고객지원
"스스로 해결" 페이지에서 실제 조치 단계까지 수집해서 냉장고·세탁기도 추가했다.

| 파일 | 카테고리 | 항목 수 |
|---|---|---|
| `data/lg_aircon_errors.json` | 에어컨 | 11 |
| `data/lg_fridge_errors.json` | 냉장고 | 5 (`dH/H`, `FF/rF`, `CH/CL`, `H1/H2`, `CO`) |
| `data/lg_washer_errors.json` | 세탁기 | 10 (`IE`, `LE`, `UE`, `dE`, `OE`, `FE`, `FF`, `tE`, `PE`, `tCL`) |

`db/seed_error_codes.py`를 세 카테고리를 한 번에 시딩하도록 리팩터링, `data/error_codes.db`를
초기화 후 재시딩 → **총 26개 항목**.

- 같은 코드 문자열이 카테고리마다 다른 의미인 경우(예: `FF` = 냉장고에서는 팬모터 이상,
  세탁기에서는 동결 감지)는 에어컨의 `F4`(CH38/CH90-91 이중 의미) 패턴과 동일하게 처리 —
  RDB가 두 항목을 모두 반환하고 LLM이 구분해서 설명.
- 라우팅 테스트 완료: `dH`, `H1`, `IE`, `UE`, `FF`(중의적 케이스 포함) 전부 RDB 경로로 정확히
  매칭 확인.

사용자가 "문서마다 거의 똑같이 복붙된 것 같다"고 언급한 부분을 실제로 검증함.
에어컨 두 모델(FQ18GU1BHN vs FQ16FV6EDN)의 "냄새 제거하기" 섹션을 비교한 결과
**텍스트 유사도 98.78%** (difflib) — 사실상 보일러플레이트 복붙 수준.

→ 정확 모델 매칭이 없을 때 "정보 없음"이라 답하지 않고 유사 모델 사례를 자연스럽게
답변하는 현재의 폴백 설계(`pipeline/query_engine.py`)가 문서 특성에 부합한다는 근거 확보.

## 5. 경쟁 서비스(LG ThinQ / 삼성 SmartThings) 리서치 및 차별점 정리

이미 수집한 LG 매뉴얼 원문("고장 진단하기" 섹션)을 근거로 확인한 사실:
- LG ThinQ의 "스마트 진단"은 **사용자가 앱에서 직접 실행해야 하는 pull 방식** (자동 push 아님)
- 매뉴얼에 나오는 Push 메시지는 고장 알림이 아니라 **"UP가전 업그레이드" 알림**
- 별도로 **"ThinQ ON 케어 알림"**이라는 진짜 선제적(push) 이상감지 기능이 있지만
  **냉장고·김치냉장고·정수기·와인냉장고·에어컨·전기쿡탑 6개 품목 한정** (세탁기·건조기 제외)
- 삼성 "AI 사전케어"는 구독가전 10개 품목(세탁기·건조기 포함)에서 유사 기능 제공

**방어 가능한 차별점**:
1. 브랜드 무관 (ThinQ=LG만, SmartThings=삼성만 / 우리는 한 대화창에서 다 처리)
2. 와이파이 미연결 구형·저가 모델도 커버 (ThinQ 기능은 전부 "와이파이 장착 모델" 전제)
3. 앱설치·회원가입·제품등록 없이 즉시 사용 가능 (진입장벽 차이)
4. 고장뿐 아니라 "사용법" 질문까지 자연어로 커버

**솔직히 인정해야 할 한계**: 우리는 구조적으로 reactive(사용자가 먼저 물어봐야 답함).
ThinQ ON 케어 알림처럼 기기가 스스로 이상을 감지해 먼저 알려주는 proactive 알림은
센서·커넥티비티가 있어야만 가능한 영역이라 텍스트 기반 RAG로는 원천적으로 불가능.
"우리가 더 정확하게 진단한다"는 카피는 위험함 — ThinQ 스마트진단은 실제 기기 센서값을
읽는 반면 우리는 사용자의 말(증상 설명)에만 의존하므로 정확도 경쟁에서는 불리할 수 있음.
